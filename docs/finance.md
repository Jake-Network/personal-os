# 로컬 재무 기록과 시세

계좌·잔액·보유 수량·평균단가·부채·거래는 이 컴퓨터의 DB가 원본입니다. Google 연결 없이 입력하고 조회할 수 있습니다. 대시보드와 상담도 같은 로컬 기록을 사용합니다. **자산** 영역의 탭에서 관리합니다. `/finance`(개요)는 백엔드가 계산한 순자산·생활비 현금·투자 평가액과 항목별 확인 필요 표시를, `/finance/accounts`는 계좌·부채·기타 자산과 입력 완료 확인을, `/finance/investments`는 보유 종목과 환율을, `/finance/cashflow`는 수입·지출·거래와 예정 지출을 모은 장부를, `/finance/history`는 월말 체크인과 기록을 보여줍니다. `/finance/transactions`는 장부로 이동합니다. Google 시세 연결은 `/settings/market`에 있습니다. 예전 `/data/*`, `/finance/records` 주소는 새 화면으로 이동합니다. 누락된 가격·환율·기준일은 0으로 대체하지 않습니다.

보유 수량은 0 이상의 정수로 입력합니다. 화면은 정수 뒤의 불필요한 소수점 0을 생략합니다. 기존 소수 수량 기록은 자동 반올림하지 않고 보존하며, 수정할 때 정수 수량을 확인해 입력하세요.

상담에서 티커·통화·수량·평균 매입가를 말해 보유 종목을 기록할 수 있습니다. 거래소가 없는 미국 티커는 [Nasdaq 공식 종목 목록](https://www.nasdaqtrader.com/trader.aspx?id=symboldirdefs)에서 거래소를 자동 확인합니다. NASDAQ·NYSE·NYSEARCA·NYSEAMERICAN을 지원하며, 미등록·여러 후보·조회 실패에서는 추측하지 않고 보유 사실을 먼저 저장한 뒤 시세 연결을 대기로 표시합니다. 목록 전체를 내려받으므로 티커·수량·원가·계좌 정보가 조회 서버로 전송되지 않습니다. 기존에 거래소 없이 저장한 자동 시세 보유분도 다음 시세 갱신에서 다시 확인합니다. 기존 종목과 유일하게 일치하면 저장된 종목·통화를 사용하고, 같은 종목이 여러 계좌·거래소에 있으면 대상을 확인합니다. 같은 티커를 다른 계좌의 별도 보유분으로 추가하면 독립된 수량·평균 매입가·포지션을 보존합니다. 등록된 계좌를 지정할 수 있고, 계좌명이 아직 없어도 계좌 미지정으로 별도 저장합니다. 기존 보유분의 수량·원가는 바꾸지 않습니다. 같은 계좌의 기존 보유량을 변경할 때는 추가 수량인지 현재 총수량인지 구분하며, 확인 질문에 답하면 미완료 항목만 이어서 처리합니다. 완료된 항목을 반복 저장하지 않고, 기존 수량·평균 매입가를 바꾸려면 정정할 값을 명시해야 합니다. “응 해줘 그리고 최신 현재가 시세 갱신해줘”처럼 저장 확인과 시세 갱신을 함께 요청할 수도 있습니다. 보유 기록을 먼저 저장한 뒤 기존 시세 갱신 정책으로 조회하며, Google 연결·5분 조회 제한·수식 계산 대기·부분 성공·실패를 별도로 표시합니다.

보유 종목의 **평균 매수가**에는 1주당 매입 가격을 종목 통화로 입력합니다. 여러 번 샀다면 평균 단가를 기록하세요. 저장 후 자동 시세를 조회하거나 기준일과 함께 현재가를 직접 입력하면 매입금액·평가손익·수익률을 표시합니다. 매입금액은 `수량 × 평균 매수가`, 평가손익은 `수량 × (현재가 − 평균 매수가)`, 수익률은 `(현재가 − 평균 매수가) ÷ 평균 매수가 × 100`이며 백엔드에서 계산합니다. 수익률과 종목 통화 기준 손익에는 환율 변동·수수료·세금·배당을 포함하지 않습니다. 매수가나 유효한 시세가 없으면 수익률을 표시하지 않으며, 수량 또는 매수가가 0이면 수익률을 계산하지 않습니다. 환율이 없어도 종목 통화 기준 손익·수익률은 볼 수 있지만 원화 평가액은 확인이 필요합니다. 오래된 시세의 계산에는 확인 필요 표시가 함께 붙습니다.

현재 원화 평가는 통화쌍별로 1건만 보관하는 현재 환율을 사용합니다. 시세 갱신은 이 값과 기준 시각을 덮어쓰고(이전 값과 같아도 기준 시각은 갱신), 더 늦은 시각으로 직접 입력한 값은 덮어쓰지 않습니다. 이미 있는 통화쌍을 다시 추가하면 기존 값을 바꿉니다. 조회 원본은 시세 관측 이력에 남고, 월말 기록·상담 근거는 당시 사용한 환율을 자체적으로 보존합니다. 미래 시각의 환율은 사용하지 않고, 오래된 환율에는 확인 필요 표시를 유지합니다. 과거 월말 평가는 별도의 역사적 근거를 사용합니다.

## Google은 시세 전용

`/settings/market`에서 Google 연결 후 **시세 파일 만들기**를 선택합니다. 앱이 새 파일에 `Quotes`와 `FX`만 생성합니다. 전송 값은 정규화한 거래소·티커·통화쌍과 서버가 생성한 수식입니다. 계좌명·수량·원가·평가액·로컬 ID·메모는 보내지 않습니다. Google에는 조회 티커 목록이 남습니다.

운영 Docker의 Sheets 요청은 허용된 Google 호스트만 통과시키는 egress 프록시를 사용합니다. Google 클라이언트의 프록시 지원에 필요한 `PySocks`도 앱 의존성에 포함됩니다. Google 연결 후 파일 생성에서 `Unable to find the server at sheets.googleapis.com`이 발생한다면 이 의존성이 없는 이전 이미지인지 확인하고 앱 이미지를 다시 빌드하세요. 프록시를 우회하거나 외부 호스트 허용 범위를 넓힐 필요는 없습니다.

Google Cloud에서 Sheets API를 활성화하고 웹 애플리케이션 OAuth 클라이언트를 발급합니다. 요청 scope는 `openid`, `email`, `https://www.googleapis.com/auth/drive.file`입니다. `drive.file`은 특정 파일 접근 권한이며 탭 단위 제한이 아닙니다. 기존 자산 파일을 재사용하지 않습니다. [Google 공식 scope 설명](https://developers.google.com/workspace/sheets/api/scopes)

```dotenv
GOOGLE_OAUTH_CLIENT_ID=your-client-id
GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
# 운영용 compose에서는 웹 서버를 통해 callback을 전달합니다.
GOOGLE_OAUTH_REDIRECT_URI=http://127.0.0.1:5173/api/finance/google/callback
```

네이티브 개발에서 백엔드로 직접 callback을 받으려면 포트를 8000으로 설정하고 같은 URI를 Google Console에 등록합니다. 브라우저의 호스트는 항상 같아야 합니다. `localhost`와 `127.0.0.1`은 다른 쿠키 호스트입니다. OAuth 시작 시 앱 잠금이 해제되어 있어야 하며, 잠금·세션 만료 후 callback은 거부됩니다. Google과 ChatGPT 연결은 서로 독립입니다.

과거의 `spreadsheets` 또는 `spreadsheets.readonly` 승인은 코드의 scope 변경만으로 철회되지 않습니다. [Google 계정 연결 관리](https://myaccount.google.com/connections)에서 기존 승인을 해제하고 다시 연결하세요. 과거 Google 파일의 개인정보도 자동 삭제하지 않습니다. 이전 완료 후 원격 파일 잔존 여부를 직접 확인하세요.

Google 계정을 바꾼 경우 `/settings/market`의 **현재 계정으로 새 시세 파일 연결**을 선택하세요. 현재 계정에 새 Quotes/FX 파일을 만든 뒤 연결을 교체합니다. 생성 실패나 도중 계정 변경 시 기존 연결을 유지하며, 이전 Google 파일과 로컬 보유 내역·관측 이력은 보존합니다. 새 연결은 갱신 제한을 초기화하므로 즉시 시세 갱신을 시작할 수 있습니다.

수동·자동 갱신은 5분 공통 제한을 적용합니다. 같은 종목은 여러 계좌에 있어도 한 번만 조회합니다. 새 관측이 아니면 이전 관측 시각을 갱신하지 않습니다. 오류·계산 대기·미지원 종목은 이전 유효 관측을 보존하며 정상 가격으로 바꾸지 않습니다. 미지원 종목에는 출처와 날짜가 있는 수동 가격을 입력하세요. Google 시세는 최대 20분 지연될 수 있고 모든 시장·종목을 지원하지 않습니다. 과거 GOOGLEFINANCE 배열은 Sheets API에서 조회할 수 없으므로 월말 종가 자료로 쓰지 않습니다. [GOOGLEFINANCE 공식 설명](https://support.google.com/docs/answer/3093281?hl=en)

자산 개요(`/finance`)의 **시세 갱신**과 투자 탭의 **시세 조회**는 같은 갱신 경로를 사용합니다. 조회 제한 중에는 새 요청을 보내지 않고 다시 조회할 수 있는 남은 시간과 이전 오류를 표시합니다. 새 종목을 추가한 직후에는 이 제한과 Google의 수식 계산 대기로 가격 반영이 늦을 수 있습니다. 거래소를 포함한 Google 코드로 입력하세요. 예: `NASDAQ:NVDA`, `NYSEARCA:SCHD`, `NYSEARCA:IAUM`. NYSE American은 `NYSEAMERICAN:종목코드`를 사용합니다. 가격 반영 대기·연결 필요·실패를 갱신 성공과 구분해 표시합니다. 일부 종목만 갱신되면 **일부 시세를 갱신했습니다**로 알리고 미지원·오류 종목의 안내를 함께 표시합니다.

## 기존 자료 이전

기존 `PortfolioImport`와 월별 스냅샷은 보존됩니다. `/settings/market`의 **예전 Sheets 자료 옮기기**에서 저장된 가져오기 번호(import ID)의 행·누락·충돌을 먼저 확인하고 편입합니다. 원본 파일·계정·행 ID 매핑을 보존하므로 같은 import를 다시 실행해도 중복 생성하지 않습니다. 티커만 같다는 이유로 다른 계좌의 행을 합치지 않습니다. 과거 스냅샷과 수정본은 재계산하지 않습니다.

기존 개인 재무 시트 설정·검증·동기화 API는 종료되었습니다. 시세 연결은 로컬 데이터 편집 권한이나 원본을 결정하지 않습니다. 기존 ADC로 다른 계정에 자동 대체하지 않습니다.

## 장부

`/finance/cashflow`에서 날짜·수입/지출·금액·분류·메모를 입력합니다. 기본값은 오늘·지출·원화이며 식비·교통·주거·생활·건강·여가 등의 추천 분류를 선택하거나 직접 입력할 수 있습니다. 수입을 선택하면 급여·상여금·사업소득·부수입·이자·배당 등 수입 분류만, 지출을 선택하면 식비·교통·주거 등 지출 분류만 추천합니다. 수입·지출 구분을 바꾸면 이전 분류 선택은 초기화합니다. 분류를 비워 두면 **미분류**로 표시합니다. 일반 가계부 기록은 수정·삭제할 수 있고, 기존 거래 원장의 수입·배당·이자·지출·수수료·세금은 함께 조회하되 잘못된 거래는 취소 기록을 남깁니다. 기록의 원본 종류와 번호가 함께 유지되므로 같은 번호나 같은 날짜·금액의 두 기록도 서로 다른 기록입니다.

월을 선택하면 기록된 수입·지출·수지, 분류별 지출 금액·비중과 최근 6개월 추이를 확인할 수 있습니다. 구분·분류·메모 검색 조건은 목록과 선택 월 합계에 함께 적용하며 합계는 현재 페이지 밖의 기록도 포함합니다. 기록이 없는 월은 **미기록**이며 수지는 기록된 수입과 지출의 차액입니다. 실제 저축액이나 계좌 잔액을 뜻하지 않습니다. 가계부 추가·수정·삭제와 거래 취소는 계좌 잔액을 자동으로 바꾸지 않습니다.

새 가계부 기록은 원화만 입력합니다. 합계·분류별 지출·추이는 상담과 같은 설정의 기준 통화(기본 원화)로 집계합니다. 다른 통화의 기록은 원통화로 확인하고 정정할 수 있지만 자동 환산하지 않으며 제외 건수를 표시합니다. 통화가 비어 있는 과거 거래는 외화 건수에 포함하지 않고 **통화 미기록**으로 구분하며 합계에서 제외합니다. 금액이나 통화가 빠진 기록이 월평균 기간에 있으면 월평균과 부분 기록 추정값을 제공하지 않고 불완전한 근거임을 표시합니다. 월 경계는 앱 시간대를 따릅니다. 이체·매매·상환과 취소된 원거래는 소비 집계에서 제외하며 다른 달에 남긴 취소도 원거래 집계에 반영합니다. 품질 경고는 종류·분류·검색어 등 선택한 조건의 6개월 기록을 기준으로 계산하며 페이지 이동에 따라 달라지지 않습니다. 해당 기록에 일반 가계부와 취소되지 않은 거래가 함께 있으면 중복 입력 확인 경고를 표시합니다. 비슷한 기록을 자동으로 합치거나 이전하지 않으므로 같은 지출을 두 입력 경로에 중복 기록하지 마세요.

대시보드와 상담은 가계부와 같은 현금흐름 원본과 취소 규칙을 사용합니다. 상담의 월평균은 최근 3개 완결 월을 대상으로 하므로 선택 월의 합계와 기간이 다릅니다. 공유를 제외한 기록은 상담 계산과 해당 기록을 사용했던 과거 대화의 재전송에서도 제외됩니다. 로컬 대시보드 표시는 이 외부 공유 설정과 독립적입니다. 예산·반복 지출·은행 및 카드 연결은 지원하지 않습니다. CSV 가져오기는 기존 가져오기 화면에서 진행합니다.

## 잔고 확인과 월말 체크인

계좌의 `잔고 그대로 맞음`은 금액을 다시 입력하지 않고 서버에서 기준일만 오늘로 확인합니다. 다른 탭에서 수정됐다면 최신 값을 다시 확인해야 합니다. 같은 날 반복 확인은 중복 이력을 만들지 않습니다. 계좌·부채·기타 자산의 같은 금액 확인은 변경 기록에서 `기준일 확인`으로 구분합니다. 현재 평가의 3일 기준과 상담의 45일 기준은 별도입니다. 부채가 없더라도 입력 범위에서 부채 입력 완료를 확인하면 미기록 경고가 사라집니다. 확인하지 않은 0건은 미기록 상태를 유지합니다.

`/finance/history`의 월말 체크인은 오늘 잔고 확인 → 입력 범위 확인 → 지난달 근거 입력·월말 기록 순서입니다. 기본 대상은 최근 완료된 달이며 행별 저장은 즉시 반영됩니다. 중간에 나가거나 일부 저장이 실패해도 성공한 저장은 남습니다. 오늘 확인과 과거 월말 기록의 완료 상태는 별도로 표시합니다. 당시 잔고·수량·가격·환율 근거가 부족하면 오늘 확인만 완료할 수 있고, 이미 존재하는 월 기록은 정정으로 연결합니다.

## 거래와 월마감

생활 수입·지출과 이체·매매·배당·이자·수수료·세금·상환은 `/finance/cashflow` 장부에서 종류를 구분해 기록합니다. 전체·수입·지출·이체·매수·매도·상환·권리변동·취소 필터와 예정 지출 탭을 사용합니다. CSV 가져오기와 오늘 평가 기록 진입점도 장부에서 찾을 수 있습니다. 거래 기록은 수정하지 않고, 잘못 기록한 거래는 목록의 취소 기록으로 되돌립니다. 발생일과 기록 시각을 구분하고 이체를 수입으로 집계하지 않습니다. 거래 입력은 기록이며 잔액·보유 수량에 자동 반영됐다고 가정하지 않습니다. 권리변동 역시 확인된 수량을 직접 기록하며 가격 변화로 추정하지 않습니다.

**오늘 평가액 기록**(일별 관측 평가 저장)은 확정 월말 스냅샷과 다릅니다. `/finance/history`의 **월말 기록 만들기**에서 과거 수량·잔액·가격·환율·포함 범위의 근거를 명시합니다. 현재 수량이나 현재 가격으로 과거 공백을 채우지 않습니다. 불완전한 합계와 누락 월은 화면에 표시됩니다. 월별 차이는 관측 차이이며 수익이나 저축으로 단정하지 않습니다. 정정은 원래 기록과 revision 연결을 남기는 새 기록이며, 화면에서는 각 달의 **변경 기록**(최초 기록·정정 순서)으로 보여줍니다.

연간 거래 집계는 기록된 현금흐름의 범위를 나타냅니다. 기록 누락을 0으로 확정하거나 근거 없는 성과·원인 분석을 하지 않습니다. 생활비 런웨이는 생활비로 사용할 수 있는 유동성과 기존 지출 충족 조건을 따릅니다.

대시보드와 상담의 월평균 수입·지출에는 기존 수입·지출 기록과 거래 기록을 함께 합산합니다. 거래의 배당·이자는 수입, 수수료·세금은 지출이며 이체·매매·상환은 생활비에 포함하지 않습니다. 취소 거래는 발생 기간 밖에서 취소했더라도 원거래를 집계에서 제외합니다. 발생 월은 앱 시간대 기준이며 미래 거래는 집계하지 않습니다. 최근 3개 완결 월 모두 지출 기록이 있어야 생활비 런웨이를 계산합니다.

장부에 함께 표시되는 두 원본의 기록은 독립적입니다. 같은 지출을 양쪽에 중복 입력하지 마세요. 기존 기록과 거래를 함께 사용하면 혼합 출처 안내가 표시되며 날짜·금액이 비슷하다는 이유로 임의 삭제하거나 합치지 않습니다. 현금 계좌가 없고 현금 기록 범위도 확인하지 않았다면 현금은 0원이 아닌 미기록으로 표시하고 런웨이를 계산하지 않습니다. 현금 범위를 명시적으로 확인한 경우 실제 0원은 0원으로 유지합니다. 범위 확인은 `/finance/accounts`의 **입력 완료 확인**에서 합니다.

화면은 백엔드의 평가 결과(영문 사유)를 한국어로 바꿔 각 항목 옆 **확인 필요**·**일부 제외** 배지에 보여줍니다. 계산 방식 설명은 각 섹션의 안내(ⓘ)에 있습니다.

## Database upgrades

Docker 컨테이너는 서버 실행 전에 DB 준비와 migration 잠금을 기다리고 이미지에 포함된 Alembic `head`까지 자동 업그레이드합니다. 실패하면 서버를 시작하지 않습니다. 기존 설치의 이미지를 교체하기 전에 앱과 worker의 쓰기를 중지하고 DB·문서·키·설정을 함께 백업하세요. PostgreSQL 백업은 자동으로 생성되지 않습니다.

DB 준비·잠금 대기 한도는 `PERSONAL_OS_MIGRATION_TIMEOUT_SECONDS`(기본 `60`초)로 설정합니다. 정비 명령에서 자동 업그레이드를 건너뛰려면 `PERSONAL_OS_AUTO_MIGRATE=0`을 지정합니다. 이력이 없는 기존 DB는 [명시적 전환](documents.md#기존-create_all-db의-명시적-전환)이 필요하며, 이미지가 모르는 revision도 시작을 거부합니다. 자동 stamp나 downgrade는 수행하지 않습니다.

네이티브 `uvicorn` 실행은 빈 DB만 초기화합니다. 기존 DB를 수동으로 확인·업그레이드할 때는 다음 명령을 사용합니다.

```bash
uv run python -m app.modules.database.migration_manager
uv run python -m app.modules.database.migration_manager --apply --backup-dir /encrypted/migration-backups --backup-key-dir /separate/private/migration-backup-keys
```

첫 명령은 애플리케이션 스키마를 바꾸지 않는 계획입니다. 비교용 임시 스키마는 종료 시 롤백합니다. `--apply`는 PostgreSQL 클라이언트의 `pg_dump`로 암호화 복구 지점을 만들고 파일을 검증한 뒤에만 stamp·트리거·upgrade를 수행합니다. 도구 누락·백업 실패 시 DB 변경 전에 중단합니다. `service=` 또는 환경의 `PGSERVICE`는 다른 DB를 선택할 수 있어 거부합니다. 명시적 연결 설정을 사용하고 `PGSERVICE`를 해제하세요. 안전한 libpq 환경 변수로 전달할 수 없는 연결 옵션도 조용히 무시하지 않고 중단합니다. 백업 폴더와 키 폴더는 서로 분리하고 디렉터리 `0700`·파일 `0600` 권한 및 암호화된 저장소를 사용합니다. 기본 백업은 데이터 폴더의 `migration-backups`, 키는 `~/.local/share/personal-os/migration-backup-keys`에 저장합니다. 앱 쓰기를 중지하고 문서·토큰 암호화 키도 별도 보존하며, 실제 전환 전 격리 복원 확인은 계속 수행하세요. Docker 자동 업그레이드는 기존 운영자 백업 절차를 유지합니다. `stamp head`, 테이블 재생성, 볼륨 삭제로 불일치를 덮지 않습니다. 백업은 [README](../README.md)의 암호화 절차를 따릅니다.
