# Personal OS 버그 진단

루트 `AGENTS.md`와 변경 영역의 지침을 따른다. 원본의 재현 중심 절차를 유지하되 재현 환경이 없어도 정적 조사와 합성 재현을 계속할 수 있게 조정했다. 커밋·배포·실제 외부 쓰기는 기존 요청 범위를 따른다. 원본 저작권은 [MIT 라이선스](../LICENSE.mattpocock)에 보존한다.

## 증상과 재현 신호

1. 사용자가 본 증상, 기대 결과, 발생 조건을 구분한다. 현재 Git 상태와 관련 호출 경로부터 확인한다. 모르는 내용은 추측으로 채우지 않는다.
2. 증상을 판별하는 가장 빠른 반복 수단을 만든다. 기존 테스트, 합성 요청, 로컬 HTTP·SSE, 브라우저 재현 순으로 적합한 것을 고른다. 예외가 없다는 조건보다 누락 이벤트·잘못된 payload·중복 호출 같은 실제 증상을 검사한다.
3. 명령을 실제로 실행하고 실패 신호를 확인한다. 입력·단계를 하나씩 줄이며 같은 증상이 남는지 확인한다. 개인 DB·문서·토큰을 재현 fixture나 캡처에 넣지 않는다. 필요한 구조만 합성하고 출력에는 비밀·개인 정보를 제거한다.

간헐적 문제는 시간·난수·작업 순서와 동시 실행 조건을 통제해 재현 빈도를 기록한다. 고정된 횟수의 반복이나 sleep을 무조건 추가하지 않는다. 운영 DB나 외부 유료 호출에 스트레스 루프를 실행하지 않는다.

재현 환경이 없으면 시도한 것과 한계를 밝히고 정적 호출 경로 조사·합성 재현을 계속한다. 이때 원인 후보와 확인된 원인을 구분한다. 실제 환경 접근이나 캡처 없이는 진행할 수 없는 지점에서만 필요한 정보를 요청한다.

## 가설을 구분하는 조사

- 모호한 문제는 유력 가설 몇 개와 각 가설이 맞을 때 달라질 관찰값을 짧게 제시하고 검증을 진행한다. 명백한 단일 원인에 여러 가설을 억지로 만들지 않는다.
- 가설마다 변수 하나를 바꾸거나 경계 한 곳을 계측한다. 임시 로그에는 고유 표식을 붙이고 내용 대신 이벤트 종류·횟수·소요 시간 등 필요한 신호만 기록한다.
- 성능 문제는 동일한 합성 입력·환경에서 기준값부터 측정한다. 상담 지연은 컨텍스트 조회·조립, 대기, 모델 첫 응답, 스트리밍 전송을 구분한다. 가짜 모델 지연과 실제 제공자 지연을 혼동하지 않는다.

## 조사 경로 선택

- 상담·SSE: `app/modules/advisor/runtime/service.py` → `graph.py` → `context.py`와 Gateway, 프런트엔드 실행 이벤트·공용 SSE 처리를 따라간다. 구독 해제와 실행 중지, checkpoint 소유권, lease·generation, 외부 호출 완료 여부를 구분한다. 완료가 불명확한 모델 호출을 재현 목적으로 자동 재호출하지 않는다.
- 개인정보·근거: 요청별 필터뿐 아니라 과거 메시지·요약·스냅샷에서 최종 모델 payload까지 확인한다. `tests/test_privacy_history.py`, `tests/test_context_budget.py`를 출발점으로 삼는다.
- 재무·DB·연결: Decimal 계산, 누락 표시, 요청 ID·버전, 트랜잭션과 자격증명 갱신 경계를 확인한다. 테스트는 `tests/conftest.py`의 폐기용 DB 조건을 지킨다. 실제 DB를 stamp·초기화해 증상을 지우지 않는다.
- 프런트엔드: `frontend/AGENTS.md`의 관련 테스트·브라우저 절차를 따른다. 정적 검사 통과를 실제 화면 재현 성공으로 보고하지 않는다.

## 수정과 종료

재현된 원인은 올바른 호출 경계의 실패 테스트로 고정한 뒤 최소 수정한다. [Personal OS TDD](../personal-os-tdd/SKILL.md)의 검증 선택을 사용한다. 적합한 경계가 없으면 이유와 대체 검증을 보고하며 이번 요청과 관계없는 구조 개편은 분리한다.

원래 시나리오와 회귀 테스트를 다시 실행하고 임시 계측·재현 파일을 정리한다. 기존 사용자 파일은 보존한다. 완료 보고는 증상, 확인된 원인과 근거, 수정, 실행한 검증, 재현·외부 연동의 남은 한계를 담는다. 재현하지 못한 증상을 해결됐다고 단정하지 않는다.
