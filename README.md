# Personal OS — 로컬 개인 기록과 의사결정

Local, single-user FastAPI backend. The advisor answers from your own Personal OS data and calls
models through **Sign in with ChatGPT** (ChatGPT plan usage via the Responses API). It never falls
back to paid API billing.

## Run with Docker (backend + PostgreSQL)

```bash
cp docker/env.sample docker/.env        # set POSTGRES_PASSWORD
docker compose -f docker/docker-compose.yml up -d --build
cd frontend && corepack yarn install && corepack yarn dev # FE runs on the host, proxies /api to 127.0.0.1:8000
```

- `app` mounts `./app` and runs uvicorn with `--reload`. Polling is forced, because a WSL `/mnt/c` mount sends no file events.
- Before starting the server, the container waits for the database, acquires a migration lock, and upgrades it to the image's Alembic `head`. A failed migration prevents server startup. Back up an existing installation before deploying a newer image.
- Volumes: `db_data` (PostgreSQL) and `app_data` (generated token-encryption key, `0600`). `down -v` deletes both.
- Ports bind to `127.0.0.1` only. If you change `API_PORT`, the OAuth redirect follows it (`http://127.0.0.1:${API_PORT}/auth/callback`).
- Never point tests at the compose DB (or any personal database): the suite drops tables. See [Tests](#tests).

## Run natively (SQLite)

```bash
uv sync
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log # port must equal OAUTH_CALLBACK_PORT
```

### Tests

Tests run only on a disposable PostgreSQL container, separate from the operating DB, and never on SQLite:

```bash
docker run -d --rm --name personal-os-test-pg -e POSTGRES_USER=personal_os -e POSTGRES_PASSWORD=personal_os \
  -e POSTGRES_DB=personal_os_test -p 127.0.0.1:55432:5432 pgvector/pgvector:pg17
docker exec personal-os-test-pg psql -U personal_os -d personal_os_test -c "CREATE EXTENSION IF NOT EXISTS vector"
TEST_DATABASE_URL=postgresql+psycopg://personal_os:personal_os@127.0.0.1:55432/personal_os_test uv run pytest -q
```

Export the backend contract locally before generating the authenticated API client:

```bash
uv run python -c 'import json; from pathlib import Path; from app.main import app; Path("/tmp/personal-os-openapi.json").write_text(json.dumps(app.openapi()))'
```

Frontend (Next.js 16 App Router + React 19, Korean UI). Same stack as qurify-fe: TanStack Query hooks generated by
orval, axios, Tailwind + shadcn/ui (Radix), react-hook-form + zod, Vitest, ESLint + Prettier, yarn.
`next.config.ts` rewrites `/api/*` and `/openapi.json` to `SERVER_DOMAIN` (default `http://127.0.0.1:8000`):

```bash
cd frontend
corepack yarn install
corepack yarn dev            # http://127.0.0.1:5173  (FRONTEND_URL must match for the OAuth redirect back)
OPENAPI_TARGET=/tmp/personal-os-openapi.json corepack yarn generate-api # use a saved backend schema; OpenAPI is authenticated
corepack yarn lint && corepack yarn typecheck && corepack yarn test
corepack yarn build
```

- Response compression is off and the proxy timeout is 10 minutes, so advisor progress events pass through the rewrite unbuffered. Answer text is shown after validation.
- On a WSL `/mnt/c` checkout the dev server polls for file changes (`watchOptions.pollIntervalMs`).

Screens: dashboard with an advisor side panel, the AI 상담 page (conversation list, durable chat with progress events,
per-request sharing toggles, Context Inspector, snapshot comparison), approvals, memory and decision
journal, data management, Settings → AI Provider, and data-sharing settings. Data-entry forms are
generated from the backend's OpenAPI schemas, so the frontend has no second copy of field definitions.

The owner sets a password on first use. Server-side sessions, HttpOnly cookies, CSRF and exact Origin checks protect personal APIs. The app locks at startup, after 15 minutes without user activity, or from the lock button. Polling does not renew the idle deadline. Locking clears browser caches in every tab and closes advisor subscriptions. Explicitly pressing the lock button also revokes consultation execution authority; an expired browser session alone does not cancel an authorized server run. Approved document-indexing workers continue. This lock does not remove database decryption keys; OS disk encryption remains a separate control.

Settings come from environment variables (see `.env.example`); `.env` is not loaded automatically.
Calendar words such as 오늘 / 이번 주 / 다음 달 resolve in `PERSONAL_OS_TIMEZONE` (default `Asia/Seoul`).
Docker startup upgrades empty and versioned databases to the committed Alembic `head` before starting the server. Database readiness and migration-lock waits are bounded by `PERSONAL_OS_MIGRATION_TIMEOUT_SECONDS` (default `60`). Set `PERSONAL_OS_AUTO_MIGRATE=0` for maintenance commands that must bypass this startup step. Databases with tables but no Alembic history, or with a revision unknown to the image, require explicit intervention; startup never stamps or downgrades them. Native `uvicorn` startup initializes empty databases only; existing databases still use the explicit upgrade command:
`uv run python -m app.modules.database.migration_manager` shows the plan (read-only) and `--apply`
performs it, after backing up a SQLite file (see [Finance setup](docs/finance.md#database-upgrades)). Migration `0005_manual_value_history` adds an append-only log of
manual balance / quantity / average-cost edits and backfills one `baseline` row per existing value;
it never modifies existing rows.

Before upgrading an existing installation, back up the database, documents and token-encryption key and stop application writes. Start the updated Docker container to apply migrations automatically, or run `uv run python -m app.modules.database.migration_manager --apply` for a native installation. Revisions `0010_advisor_runtime` and `0011_advisor_checkpoints` add persisted runs, events, scenarios and graph checkpoints while retaining existing conversation and memory IDs. Checkpoint tables are created by Alembic migrations; graph execution and ordinary requests do not create them.

Financial figures distinguish net worth, investable assets, cash and cash equivalents, and
*spendable liquidity* (cash-kind accounts marked liquid). Cash runway uses spendable liquidity only
and is reported as unavailable when the last three full months of expenses are not all recorded.

CI (`.github/workflows/ci.yml`, Linux) runs pytest on a PostgreSQL service (plus Alembic
upgrade/check/downgrade), and frontend lint, typecheck (`next typegen && tsc`), Vitest and build.

## 지속되는 상담 워크스페이스

`/advisor`에서 질문을 보내면 서버가 분석을 실행하고 대화와 오른쪽 근거 패널(`근거`·`비교`·`제안` 탭)에 저장된 상태를 표시합니다. 다른 화면으로 이동하거나 브라우저를 닫아도 **서버가 실행 중이면** 분석을 계속합니다. 다시 열면 완료된 답변 또는 같은 확인 질문을 불러옵니다. 앱 전체에서 한 번에 하나의 분석을 실행하며, 각 상담에는 확인 질문 대기·확인 필요 상태를 포함해 미종결 실행을 하나만 둡니다. 분석 중에도 다음 질문의 초안은 작성할 수 있습니다.

- **자동 / 깊게 분석:** 모델 호출·도구 조회·재계획 한도는 각각 6회·12회·2회와 12회·24회·3회입니다. 요약·검증·구조화된 출력의 수정 요청도 모델 호출 한도에 포함합니다. 긴 대화의 요약은 원문 출처를 보존한 과거 맥락이며 현재 잔고·일정을 대신하지 않습니다. 한도나 근거 부족은 결과의 한계 또는 오류로 표시합니다.
- **답변 필요:** 확인 질문의 선택지나 입력창으로 같은 분석에 답합니다. `아직 모름`은 미확인 조건을 한계로 남기고 조건부 답변으로 진행합니다. 확인 질문은 한 실행에서 최대 두 번만 요청합니다. 대기하는 동안 다른 상담의 분석은 실행할 수 있습니다.
- **분석 중지 / 재시도:** 진행 상태는 답변 자리에 한 줄로 표시하며 완료되면 사라집니다. 브라우저 연결 종료와 중지 요청은 별개입니다. `중지 요청 중`은 완료 확인 전 상태입니다. 실패·확인 필요 상태의 재시도는 명시적으로 요청하며 새 답변을 만듭니다(이전 답변은 보존). 서버가 중단돼 모델 호출의 완료 여부가 불명확하면 자동 재호출하지 않고 확인 필요로 둡니다.
- **비교 탭:** 목적·가정·제약과 저장된 대안을 확인합니다(대안이 있을 때만 표시). `조건 바꿔 비교`는 원래 결과를 보존하는 새 버전의 분석이며, `이 대안으로 이어가기`는 관련 후속 상담의 기준을 선택합니다. 관계없는 새 질문에는 이전 대안을 자동 적용하지 않으며 `대안 선택 해제`로 기준을 지울 수 있습니다. 한 분석에서 생성하는 대안은 최대 3개입니다. 재무·시간 결과는 필요한 입력이 있는 경우 서버가 계산하며, 미확인 값은 그대로 표시합니다.
- **근거 / 제안 탭:** 입력 중에는 보낼 데이터를 미리 보여주고, 답변의 `근거`를 누르면 그 답변 당시 데이터와 인용한 레코드(해당 화면으로 이동)를 보여줍니다. `제안` 탭은 승인 대기 행동을 모읍니다. 행동과 장기 기억은 사용자 확인 후 반영합니다. 제안 뒤 일정·목표가 바뀌면 승인은 충돌로 끝나며 새 제안이 필요합니다. 결정·회고는 기존 결정 기록에서 관리합니다.

답변은 근거·계산·출력 검증이 끝난 뒤 표시합니다. 처리 중에는 현재 단계를 보여주며, 검증 전 모델 출력은 확정된 답변으로 표시하지 않습니다.

처음 상담할 때 AI 연결 설정을 확인하세요. 입력창의 기본 도구는 공유 범위·깊게 분석·더보기·보내기입니다. 문서·과거 경험·웹 검색은 더보기에서 조절하고 변경한 설정은 칩으로 확인합니다. 웹 검색은 별도로 켜고 공개 검색어를 입력합니다. 과거 메시지 검색 결과에서도 질문을 보낼 수 있으며 새 답변을 확인하도록 최신 대화로 이동합니다. 전송 실패 후 설정을 바꾸면 이전 요청의 저장 여부를 먼저 확인하며, 이전 공유 범위의 본문을 다시 전송하지 않습니다. 입력한 질문 자체는 모델에 전달되므로 비밀번호나 인증정보를 입력하지 마세요.

LangChain 모델·조회 도구와 LangGraph 실행은 기존 모델 Gateway와 공유 검사를 사용합니다. 외부 추적 전송이나 외부 임베딩 자동 전환은 활성화하지 않습니다. 합성 데이터와 가짜 제공자 회귀 검증은 실제 제공자의 답변 품질·OAuth 연결 성공·실제 문서의 검색 품질 평가를 대신하지 않습니다.

답변의 수치 필터는 금액·재무 지표·증감률·확률에 관한 문장에서 근거에 없는 숫자를 생략합니다. 일반적인 기간·운동 페이스 계산이나 훈련 제안은 새로운 숫자가 있다는 이유만으로 삭제하지 않습니다. 사용자가 입력해 상담에 전달된 DB 값은 근거로 사용합니다. 이 필터는 문구에 따른 보조 검사이며, 통과한 수치의 정확성을 보증하지 않습니다.

저장된 최종 답변은 `결정으로 기록`하거나 👍/👎로 평가할 수 있습니다. 결정 등록·대안 선택·답변 기록은 같은 폼에서 선택·이유·예상 결과·회고일을 입력하며, 원래 답변의 근거를 보존합니다. 새로 저장하는 답변 연결 결정은 원본 메시지 ID도 보존해 재시도한 답변을 구분합니다. 기존 결정의 메시지 ID는 임의로 추정하지 않습니다. 결정 제목은 200자까지이며 질문에서 채운 기본 제목도 같은 길이로 제한합니다. 회고일은 앱 시간대 오전 9시로 저장합니다. 확인 질문과 미완성·실패 답변은 대상에서 제외됩니다. 평가는 답변별로 저장되며 같은 버튼을 다시 누르면 해제합니다. 평가와 사유는 상담 근거로 전송하지 않습니다.

홈의 `이번 주 살펴볼 것`은 모델 호출 없이 지출·목표 마감·면접·운동 기록을 확인합니다. 지출은 자료가 충분할 때만 이번 달 누적과 최근 완료된 3개월의 월평균을 비교합니다. `상담으로 이어가기`는 질문 초안만 채우며 기존 초안을 덮어쓰거나 자동 전송하지 않습니다. 상담 준비 체크리스트의 AI 연결 완료는 로컬 설정 상태이며 실제 추론 성공을 뜻하지 않습니다. 모두 충족하면 체크리스트가 숨겨집니다. 기억은 `/settings/memory`의 `AI가 아는 나`에서 관리하며 `/memory`, `/reflect/memory`도 이 화면으로 연결됩니다.

사용 후 살펴볼 지표는 재무 근거 충족률, 30일 이내 잔고 비율, 결정·회고 완료율, 메시지별 최신 👎 비율입니다. 이 지표는 답변의 계산 정확성·근거 연결·공유 제한 준수 검증을 대신하지 않으며, 별도의 자동 품질 측정 기능을 뜻하지 않습니다.

## 플레이북·학습·브리핑

상담 결과를 다음 상담의 절차로 쌓고, 사용자가 묻기 전에 확인할 일을 알려 줍니다. 모든 학습 결과는 제안으로만 저장되며 사용자가 승인하기 전에는 상담에 쓰이지 않습니다.

- **플레이북(`/reflect/playbooks`):** 상담에서 따를 확인 순서입니다. 로컬 DB에 수정 기록으로 보관하며 내용은 고쳐 쓰지 않고 새 버전을 쌓습니다. 사용자가 직접 쓰거나 고친 버전은 바로 쓰이고, 상담에서 나온 제안은 기준 버전과 비교(diff)한 뒤 승인합니다. 그 사이 플레이북이 바뀌었으면 승인할 수 없습니다. 질문에 트리거 단어가 있거나 입력창에서 `/짧은이름`으로 부르면 최대 두 개를 보냅니다. 분석 계획 단계는 제목·요약 목록만 보고 고르고, 고른 절차의 본문만 근거 데이터(`data.playbooks`)에 넣습니다. 새로 고른 절차가 있으면 본문을 불러온 뒤 그 단계에 맞춰 조사 계획을 한 번 다시 세웁니다(호출 예산이 부족하면 답변에만 쓰고 한계로 알립니다). 목록은 질문 관련성 순으로 최대 12개·4,000자까지 제공하고, 생략 수를 표시합니다. 목록에 제공한 버전은 그 실행의 이후 요청마다 전송 직전에 다시 검사해 공유 해제 후 파생 계획이 전송되지 않게 하지만, 목록에만 보인 절차는 답변의 근거가 아니므로 나중에 공유를 바꿔도 과거 답변을 막지 않습니다. 답변 당시 쓴 버전은 근거 스냅샷과 사용 기록에 남습니다. 플레이북을 삭제하면 절차와 사용 기록만 지우고, 그 절차를 쓴 답변의 근거 스냅샷은 보존합니다. 삭제한 절차의 출처 영역은 참조에 남아 그 영역의 공유를 막으면 해당 답변도 계속 보내지 않습니다. 관련 영역 중 하나라도 공유를 막았거나, `상담에 보내기`를 껐거나, 보관했거나, 학습 근거가 삭제된 플레이북은 보내지 않습니다. 예산이 부족하면 플레이북 전체를 빼고 `context_section_omitted`로 알리며 절차 중간을 자르지 않습니다.
- **저장 규칙:** 플레이북은 기록이 아니라 교훈입니다. AI가 제안한 내용에 금액·특정 날짜·레코드 참조·지시 변경 문장·비밀값·보이지 않는 제어 문자가 있으면 저장하지 않습니다. 사용자가 직접 쓴 내용은 경고와 함께 저장합니다. AI가 제안한 기억 후보에도 같은 지시·비밀값 검사를 적용합니다. 검사는 패턴 기반 보조 장치이며 통과한 내용의 안전을 보증하지 않습니다.
- **상담에서 배우기:** 답변의 `이 상담에서 배우기`는 그 상담을 다시 읽어 플레이북·기억 후보를 제안받는 AI 호출을 한 번 더 만듭니다. `/settings/agent`에서 켜면 분석이 길었거나(도구 3회 이상·재계획·확인 질문) 사용자가 정정한 상담, 결과를 기록한 결정 회고에 대해 자동으로 요청합니다(기본 꺼짐). 회고 요청도 상담과 같은 `ContextAssembler` 경로를 거치므로 **요청 시점의** 공유 범위·이력 차단·예산·스냅샷이 적용됩니다. 학습에는 과거 답변의 모델이 아닌 현재 선택한 모델을 사용합니다. 실행 권한은 요청할 때 고정되고, 앱 잠금·연결 계정·모델이 바뀌면 호출 없이 취소합니다. 상담 실행과 같은 전역 1개 실행 규칙을 따르며, 앱이 실행 중 멈춰 호출 결과가 불확실하면 자동으로 다시 호출하지 않고 실패로 두어 `/settings/jobs`에서 명시적으로 재시도하게 합니다. 선택한 답변은 최근 대화 범위를 벗어나도 원문을 예산 안에서 제공하고, 결정 회고는 요청 당시의 정확한 결과 기록을 고정합니다. 학습된 절차와 기억은 실제 회고 스냅샷의 출처를 보존하므로, 근거의 공유를 막거나 삭제하면 승인 후에도 보내지 않습니다. 선택한 과거 답변이 지금 공유 범위에서 제외되면 현재 기록만 회고하고, 그 답변을 출처로 한 기억 후보는 만들지 않습니다.
- **사용 결과를 학습에 반영:** 회고는 관련 플레이북을 쓴 최근 답변(최대 50개)의 👍/👎, 다음 질문의 정정, 결과를 기록한 결정 수를 건수로만 받아(`playbook_usage`) 반복해서 정정·낮은 평가를 받은 단계를 고치는 수정 제안을 검토합니다. 지금 공유할 수 없는 답변은 세지 않으며 대화 원문은 보내지 않습니다. 자동 학습을 켜면 플레이북을 쓴 답변에 👎를 누를 때 회고를 요청하고, 정정 질문을 회고할 때는 직전 답변이 쓴 플레이북도 함께 검토합니다. 같은 건수는 플레이북 화면에도 표시합니다.
- **이전 상담 검색:** "지난번 상담"처럼 과거 상담을 묻는 질문은 분석 계획으로 넘어가며, 계획 단계가 `search_sessions` 조회로 다른 대화를 검색합니다. 결과는 상담별 질문·답변 쌍(각 600자, 최대 4개 상담·6,000자)이고, 각 메시지가 현재 공유 범위·로컬 전용 설정·문서 범위를 통과할 때만 포함합니다. 대화 제목은 보내지 않습니다. 발췌는 근거 스냅샷에 출처로 남고 당시 기록으로 표시되며, 과거 숫자로 새 수치를 뒷받침하지 않습니다. 예산을 넘거나 일부를 생략하면 `session_search_*` 플래그로 알립니다.
- **브리핑(`/settings/jobs`):** 매일·매주 정한 시각(`PERSONAL_OS_TIMEZONE`)에 회고할 결정, 다시 확인할 기억, 다가오는 면접·목표 마감, 오래된 시세·잔고, 승인 대기 항목을 모델 없이 계산해 알림에 표시합니다. 항목이 없으면 아무것도 하지 않습니다. `AI 정리`를 켠 경우에만 항목이 있는 날 새 상담(`origin=schedule`)을 만들어 분석하고, 이전 브리핑 대화는 다시 보내지 않습니다. 보내는 영역은 항목에 필요한 범주와 사용자가 고른 범주의 교집합입니다. 회고할 결정·다시 확인할 기억·승인 대기처럼 상담 근거로 제공되지 않는 항목은 알림으로만 보여 주며 모델을 호출하지 않습니다. 켤 때의 연결·모델로만 실행하고, 바뀌면 예약을 멈추고 알립니다. 결과 제안은 승인 대기로만 들어갑니다. 앱이 꺼져 있어 놓친 날은 몰아서 실행하지 않고 가장 최근 1회만 실행합니다(기간 회고는 놓친 기간을 순서대로 처리합니다). 예약이나 AI 정리·공유 범위를 수정하면 기존 미완료 실행을 취소하며, 전송 직전에도 현재 동의를 다시 검사합니다. 모델을 깨우는 신호는 선택한 모든 관련 범주의 공유가 허용되고 해당 기록이 로컬 전용이 아닐 때만 사용합니다. 알림용 신호의 제목·개수는 모델 메시지에 넣지 않습니다.
- **상담 방식:** 말투·답변 길이·결론 우선·추가 메모를 정합니다. 시스템 규칙 뒤에 "규칙을 바꾸지 않는다"는 표시와 함께 붙으며 데이터·공유·승인 규칙은 그대로입니다.

`/approvals`에서는 여러 항목을 골라 한 번에 승인·거절할 수 있고, 학습 제안 알림에서는 제안 내용을 보고 바로 고를 수 있습니다. 아무것도 미리 선택하지 않으며, 각 항목은 서버에서 따로 처리되어 바뀌었거나 이미 처리된 항목만 실패로 표시됩니다. 일시정지한 브리핑의 `지금 실행`은 알림만 만들고 AI 정리는 하지 않습니다.

준비 알림을 읽었어도 완료·확인 필요·실패·중지 상태는 새 알림으로 갱신됩니다. 열린 알림·승인 목록은 30초마다 갱신합니다. 알림은 이 기기에서만 표시하며 모델에 보내지 않습니다. 메신저·외부 알림 연동은 없습니다. 이 기능의 회귀 검증(`tests/test_playbooks.py`, `test_agent_loop.py`, `test_agent_followups.py`, `test_agent_migration.py`)은 합성 데이터와 가짜 제공자로 전송 payload를 확인하며, 실제 모델의 학습 제안 품질은 평가하지 않습니다.

## Portfolio and monthly history

The 자산 area (`/finance`: 개요, `/finance/accounts`, `/finance/investments`, `/finance/cashflow`, `/finance/history`) evaluates local DB accounts, holdings, liabilities and FX; the quote connection lives in `/settings/market`. Google OAuth is optional and restricted to a newly created quote-only file using `drive.file`. Only tickers, currency pairs and quote formulas leave the machine; Google can retain the ticker list. Personal quantities and costs stay local. Existing Sheets imports have an explicit preview/import path; existing snapshots and corrections remain unchanged. See [Finance guide](docs/finance.md).

`/career` shows job applications and their interviews; `/career/records` links employment, roles, projects, contributions, achievements, evidence and feedback with date precision. Extracted records remain drafts until confirmed and sharing defaults to local-only. `/career/timeline` derives events from their original records. `/advisor` offers paged title/body/date search, source-linked local summary drafts, cross-conversation keyword/local embedding retrieval, and explicit company/project/decision links. `/settings/memory` stores revisions and validity intervals. Live balances and schedules always come from domain records, while derived sources are rechecked before transmission.

`/reflect` holds the decision journal and `/reflect/reviews` keeps repeated decision outcomes and month/quarter/year review drafts with frozen evidence. Confirmation is explicit. `/settings/jobs` exposes local recurring review schedules, retry and failure states; schedules are disabled until the user enables them. Review generation is deterministic and local. No background external LLM work is enabled implicitly: learning reflections and model briefings run only after the explicit opt-ins described above.

## Consultation latency and analysis depth

In `auto` depth, ordinary dialogue goes directly to one structured final answer. Explicit analysis, constrained comparisons and selected scenarios use planning, authorized read tools, server calculations, then one final answer. Auto skips separate model review, per-scenario model explanations and model-generated history summaries. It reuses source-checked summaries or the existing disclosed message excerpts; required context that exceeds the request budget still fails explicitly. Schema repair may add one call per structured stage, and essential clarification can pause a run.

`deep` retains history summarization, scenario analysis and review/replanning within the existing call limits. Structured runtime requests use provider JSON mode, followed by server validation of the domain schema. Both auto paths validate final JSON, document citations and numerical evidence, and keep proposals pending approval. A complete JSON object inside a single Markdown JSON fence is accepted; arbitrary prose, malformed JSON and invalid fields still fail validation. Repair requests and progress events include safe validation error types/field paths, without model output or personal content.

These are call-count reductions, not a wall-clock latency guarantee. Normal durable answers are published after final validation; intermediate JSON is not shown as an answer.

## Local production runtime and backup

Use the separate production compose file, not a development overlay:

```bash
cp docker/env.sample docker/.env # fill secrets on the server
# Review host disk encryption and data locations before writing personal records.
docker compose --env-file docker/.env -f docker/compose.production.yml up -d --build
```

Only the nginx entry gateway publishes `127.0.0.1:5173`. Next.js, backend, PostgreSQL and embeddings stay on an internal Docker network; the gateway forwards to Next.js and OAuth callbacks pass through the web server. There are no development source mounts or reloads. An HTTPS destination allowlist proxy mediates external calls. The browser restricts external images, frames and connections. Embedding models must be provisioned locally: the embedding container has no direct internet access. Changing local DB/embedding endpoints to arbitrary external servers is rejected in production.

Security updates must include the runtime images as well as `uv.lock` and `frontend/yarn.lock`. Python is pinned in `.python-version`, Node in `frontend/.node-version`, and the Dockerfiles pin patched runtime releases. CI audits both dependency locks; those package audits do not scan container OS packages. Use a current `uv` release (the Docker build uses 0.13.5) to install the pinned Python version. After backing up an existing installation and stopping application writes as described above, build replacement images with `docker compose --env-file docker/.env -f docker/compose.production.yml build --pull`, pull the pinned embeddings image with `docker compose --env-file docker/.env -f docker/compose.production.yml pull embeddings`, then start the stack with `docker compose --env-file docker/.env -f docker/compose.production.yml up -d`. A restart alone keeps the old image and its old dependencies. Verify the running versions after replacement; updating source files does not patch existing containers.

Checkpoint deserialization restricts object reconstruction to safe built-in types and explicitly allowlisted schema types. Revision `0016_checkpoint_task_path` adds the patched SQLite saver's pending-task path column while preserving existing checkpoint bytes and pending writes; PostgreSQL already has this column. Apply the migration before running the updated backend; runtime saver setup never creates or alters tables.

The frontend selectively resolves Tailwind 3's `postcss-selector-parser` dependency to the patched 7.x release. Yarn reports the upstream 6.x range mismatch; the application build validates compatibility. Keep this override until an upstream dependency update provides a patched parser without it.

Use `/settings/security` (설정 → 보안·백업) for read-only diagnostics. `unverified` does not prove encryption or firewall protection. In Windows/WSL, check BitLocker/device encryption and the actual WSL/Docker virtual disk location, plus DB/document/vector/temp/key storage. The app never changes OS security settings. Volumes and staging must reside on an OS-encrypted disk; Docker volumes alone do not supply this guarantee.

Install restic separately. Stop the application and workers first, keep the password file outside the backup repository, and stage on encrypted local storage:

```bash
export RESTIC_REPOSITORY=/absolute/local/encrypted-backups
export RESTIC_PASSWORD_FILE=/absolute/private/restic-password
uv run python scripts/local_backup.py backup --data-dir ./data --settings-file .env --sqlite ./data/personal_os.db --staging-dir /encrypted/staging --confirm-app-stopped --init
uv run python scripts/local_backup.py restore-check --staging-dir /encrypted/staging
```

For PostgreSQL supply `--postgres-dump /path/to/database.dump` instead of `--sqlite`, using a consistent custom-format `pg_dump` captured while writes are stopped. Add `--postgres-image personal-os-postgres-vector:17-alpine` to restore-check. Restoration is checked in a disposable directory/database; it never overwrites the running installation. Bundles include data/documents/keys/settings, Git revision and working-tree status, a source digest, migration-file hashes and data hashes. Retain the restic password and token key separately. Synthetic SQLite and PostgreSQL restore tests do not establish that a particular user's host storage is encrypted.

## External model data control

Settings → AI Provider requires account-specific user confirmation of training exclusion and retention policy before inference. Account changes/reconnection or API key rotation require confirmation again. The app cannot inspect the user's provider settings. `store: false` remains enabled; it does not mean no provider-side retention. See [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data). Category, record, document and source policies also apply to history, memories and retrieved material. Unknown or revoked provenance fails closed. No automatic paid-provider fallback exists.

```
app/

  modules/<domain>/  *_manager.py  business logic, module-level singletons
  modules/crud/      *_handler.py  ORM access only (BaseCRUDHandler)
  modules/database/  engine/session, model/ (SQLAlchemy models)
  schema/            *_schema.py  pydantic API models + internal value objects
  enums/
frontend/src/
  app/          routes; (main)/advisor/layout.tsx hosts the workspace so /advisor → /advisor/[id] keeps the stream
  api-client/   axios mutator, SSE client, error normalization; generated/ + model/ come from orval
  features/     advisor, dashboard, plan, finance, holdings, career, memory, reviews, documents, personal-data, approvals, playbooks, inbox, settings
  components/   shared UI (page header/sections, tabs, record states, calendar/); ui/ holds the shadcn primitives
  widgets/      providers, app shell, sidebar
  lib/          Korean labels, formatting, QueryClient
```

|---|---|
| OAuthAuthService | `modules/auth/oauth_manager.py` |
| ChatGPTPlanProvider / LLMGateway | `modules/llm/providers.py`, `modules/llm/llm_gateway_manager.py` |
| ContextRouter / ContextBuilder | `modules/context/routing.py`, `context_builder_manager.py` |
| Read-only agent tools | `modules/context/context_tool_manager.py` |
| ConversationRuntime / 상담 그래프·worker | `modules/advisor/runtime/` |
| 상담 이력·공유·미리보기 | `modules/advisor/advisor_manager.py`, `modules/advisor/runtime/context.py` |
| FinancialCalculator | `modules/finance/financial_calculator.py` |
| DecisionJournalService | `modules/advisor/memory_manager.py` |
| 플레이북(승인·선택·저장 규칙) | `modules/playbooks/` |
| 학습 회고·브리핑·알림·상담 방식 | `modules/agent/` |
| ConversationRepository | `modules/crud/conversation_handler.py` |

Inside a module package, files are split by role:

| File | Holds |
|---|---|
| `<name>_manager.py` | DB, network, LLM and file I/O calls and their order |
| `types.py` | dataclasses and TypedDicts passed between files (`app/schema/` is for API models only) |
| `errors.py` | domain exceptions; routers map them to HTTP |
| role-named files (`budget.py`, `valuation.py`, `parsing.py`, ...) | pure functions: parsing, checks, calculations |

A function that does no I/O does not go in a manager. `modules/crud/` holds one ORM handler per model,
re-exported from `app.modules.crud`.

## How a question is answered

1. `ContextRouter` selects the needed categories with deterministic rules, without an LLM call.
   Financial overviews and resignation planning include holdings as well as cash and debt.
   Explicit follow-ups such as `그럼 6개월이면?` retain the previous subject even when new time keywords match.
   Registered holding names/tickers can identify an investment question without a generic stock keyword;
   a company name alone does not add investments to an explicit interview or calendar question.
2. Categories the user excluded (saved in `/api/settings/privacy` or set for one request) are removed before any data is read.
3. Read-only tools query the DB through handlers. Numbers (net worth, monthly spending, weights,
   calendar conflicts) are computed in the backend with Decimal. Missing or stale data becomes a `data_quality_flags` entry, never a guessed value.
   Calendar queries use the requested day, week, month or ISO date instead of always reading the next 14 days.
   The package records the actual half-open range and timezone (currently UTC in production).
   Unsupported or multiple date ranges are flagged and only the reported default range is queried.
4. The package is frozen as a `context_snapshots` row (refs, source freshness, exact payload). If
   nothing changed since the previous turn, that snapshot is reused.
5. The request goes to `POST /v1/responses` with `store:false, stream:true`. The answer streams back
   as SSE (`context` → `delta`* → `done` | `error`).
6. ```` ```proposal ```` / ```` ```memory ```` blocks in the answer become pending items. Nothing is applied
   until `/api/proposals/{id}/approve` or `/api/memories/{id}/confirm`. Financial tables have no proposal path.

`tests/test_advisor_product_context.py` checks the complete advisor request path against synthetic personal data:
exact net worth, refreshed balances on follow-ups, registered stock mentions, requested calendar periods,
sharing exclusions and bounded history queries. The generation provider is captured in these tests;
they verify what data reaches the model, rather than grading a live model's free-form answers.

## Sign in with ChatGPT

`POST /api/settings/ai-provider/chatgpt/login` returns the authorize URL. It uses dynamic client registration on first
sign-in, PKCE S256, state + nonce, `resource=https://api.openai.com/v1`, and requests the scopes
`openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`. The callback at
`http://127.0.0.1:<port>/auth/callback` exchanges the code and verifies the ID token against OpenAI's JWKS.
It enables plan usage only if `chatgpt.tokens.use.direct` was granted. Tokens are Fernet-encrypted in
`oauth_credentials` and never returned by any endpoint. Quota (`subscription_sharing_usage_limit_exceeded`),
scope, and revoked-token errors each map to a distinct user message. None of them switches provider.

The API-key and Codex app-server providers exist behind the same interface. They become active only via
`PUT /api/settings/ai-provider/selection`. The Codex app-server provider is a stub.

## 개인 문서 상담

### 웹 검색과 본문 근거

로컬 실행과 개발 Docker에서는 상담 입력의 `웹 검색`을 켜고 별도의 `공개 검색어`를 입력할 수 있습니다.
서버 환경에 `PERSONAL_OS_WEB_SEARCH_API_KEY`로 [Brave Search API 키](https://api-dashboard.search.brave.com/app/documentation/web-search/get-started)를 설정한 뒤 백엔드를 다시 시작하세요.
네이티브 실행은 `.env`를 자동으로 읽지 않으므로 실행 환경에 변수를 전달해야 합니다.
검색 서비스 사용에는 해당 제공자의 별도 이용 조건·요금이 적용되며, ChatGPT 연결이 검색 권한을 제공하지는 않습니다.

외부 검색에는 공개 검색어만 전송합니다. 상담 질문·개인 DB·문서·대화 이력을 검색어로 자동 확장하지 않습니다.
검색 결과에서 최대 3개 페이지의 HTML·일반 텍스트 본문을 수집하고 메뉴·스크립트를 정제한 뒤 질문과 관련된 발췌를 고릅니다.
LangGraph의 `web_search` 노드가 실행된 후 기존 계획·개인 데이터 조회·계산·답변 경로로 이어집니다.
선택한 발췌와 URL·제목·발행일(있는 경우)·조회 시각·본문 해시는 기존 근거 스냅샷에 보존하고, 답변은 수집한 URL을 인용합니다.
근거 패널에서 실제 전송된 발췌와 수집 실패·예산 생략 표시를 확인할 수 있습니다. 미리보기는 웹 요청·저장·모델 호출을 하지 않습니다.

요청 한 번당 검색 한 번, 기본 최대 5개 검색 결과 후보, 페이지당 1 MB, 전체 25초로 제한합니다.
공개 IP에 연결을 고정하고 리다이렉트마다 재검사하며, 내부망·인증 포함 URL·비표준 포트를 차단합니다.
PDF·로그인·JavaScript 렌더링이 필요한 페이지와 압축 응답은 지원하지 않으며 검색 발췌로 본문 수집 성공을 대신하지 않습니다.
중지·앱 잠금은 수집도 취소하며, 중단으로 외부 호출 완료 여부가 불명확하면 자동 재호출하지 않습니다.
현재 운영 Docker(`PERSONAL_OS_PRODUCTION=true`)는 허용 목록 프록시로 임의 사이트 접속을 차단하므로 웹 수집 요청을 명시적으로 거부합니다.
운영 지원에는 별도 안전한 수집 게이트웨이가 필요하며, 이 기능 때문에 기존 외부 연결 정책을 완화하지 않습니다.

PDF·Markdown·TXT를 주제별로 올리고 기존 DB 정보와 함께 상담할 수 있습니다.
문서함, 로컬 임베딩, pgvector 설정과 공유·삭제 동작은 [문서 상담 가이드](docs/documents.md)를 참고하세요.
